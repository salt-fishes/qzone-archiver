# qzone-archiver 桌面版 ToC 化主界面设计

> 状态：方案（待评审） · 日期：2026-08-10 · 依据：M2c 现有主界面（desktop/src/renderer/src/App.vue）+ 产品定位确认 ToC

## 0. 决策记录

| 决策项 | 结论 |
|---|---|
| 产品定位 | **ToC**（个人消费者）：QQ 空间个人记忆的本地备份工具，非企业工具 |
| 心智模型 | 「记忆保险箱」：扫码登录 → 选个位置 → 开始备份 → 随时回来浏览 |
| 设计原则 | 默认值即最佳路径 / 一次只问一个问题 / 人话优先 / 进度可见结果可感 / 数据安全可视化 |
| 信息架构 | 侧边导航四视图：概览 / 备份 / 历史 / 设置（替代当前顶栏 7 按钮 + 双栏单页） |
| 保留资产 | 复古暖色设计系统、印章品牌、11 模块能力、断点续传/增量/防限流等底层能力全部保留 |
| 高级配置 | 模块细项、下载器、外部工具等折叠进「高级设置」，主流程不出现 |
| 技术栈 | 沿用 Vue3 + Pinia + vue-router（新增路由层）；渲染器重构为 views/ + components/ |
| 底线 | 现有 App.vue 的全部功能（含下载列表、日志导出、历史浏览、帮助）必须全量保留，仅重组表达 |

## 1. 背景与问题

### 1.1 现状

桌面版主界面当前是**单页双栏 + 顶栏按钮**形态（[App.vue](file:///c:/Users/15572/Documents/trae_projects/zoneexport/desktop/src/renderer/src/App.vue)）：

- 顶栏：引擎状态、登录态、历史备份/设置/帮助/刷新/退出 7 个入口
- 左栏：备份设置（保存位置 + 11 模块勾选 + 配置摘要 + 开始/暂停/恢复/取消）
- 右栏：备份进度 / 下载列表 / 运行日志
- 模态：设置（12 个 tab：公共 + 10 模块 + 开发者）、历史备份、欢迎页、帮助中心

### 1.2 与 ToC 的差距（问题清单）

| # | 问题 | 用户感受 | 影响 |
|---|---|---|---|
| P1 | 「备份」被做成配置密集型任务：11 模块 × 每模块 5-9 项设置、5 类配置概念 | 不知道哪些该选、选错会怎样 | 首备决策负担大，可能放弃 |
| P2 | 满屏技术术语：「引擎就绪」「WAF 限流」「增量 Full/Last」「导出 SPA/HTML/MD/JSON」「下载并发数」「迅雷任务数」 | 像给工程师用的 | 信任感低 |
| P3 | 无主导航，顶栏堆 7 个功能按钮 | 功能找不到、层级混乱 | 可发现性差 |
| P4 | 进度 = 百分比 + 成功/失败/跳过计数 + 控制台日志流 | 冷、无法预判剩余时间 | 长备份焦虑 |
| P5 | 默认值不友好：模块未全选、高级配置裸露 | 一键备份不可达 | 黄金路径长 |
| P6 | 安全焦虑未正面回应（FAQ 里才有「备份是否导致账号异常」） | 不敢用 | 转化流失 |

### 1.3 目标

> 让一个**从未用过该产品**的普通 QQ 用户，在 3 分钟内完成「登录 → 开始备份 → 看到进度」；备份完成后产生「我的记忆安全了」的确定感。

## 2. 设计理念（心智模型）

### 2.1 核心叙事

```
「把十几年的 QQ 空间记忆，完整搬回你的电脑，随时回看，永不丢失。」
```

- 产品词从「备份工具」改为「**记忆保险箱 / 空间档案**」。
- 每次备份是「把记忆存入保险箱」，浏览是「打开保险箱」。

### 2.2 五条设计原则

1. **默认值即最佳路径**：模块全选、全量备份、应用内下载、推荐目录。用户不碰任何设置也能得到一份完整备份。
2. **一次只问一个问题**：备份流程拆成三步向导，每步一个决策，不并行抛选项。
3. **人话优先**：界面语言描述结果而非机制（「网页版」而非「SPA」；「快速/稳妥」而非「并发数」）。
4. **进度可见、结果可感**：进度显示「正在做什么 + 已保存多少 + 预计还需多久」；完成后给出数字总结页。
5. **数据安全可视化**：登录账号明确展示、隐私承诺前置、备份频率建议出现在操作前而非 FAQ 里。

## 5. 文案体系（术语去技术化）

### 5.1 术语对照表

| 现状文案 | 新文案 | 说明 |
|---|---|---|
| 引擎就绪 / 引擎加载中 | 已连接 / 连接中 | 用户不关心引擎 |
| 开始备份 / 备份中 | 开始备份 / 正在备份 | 保留但配合步骤叙事 |
| 导出类型：SPA | 备份格式：网页版 | 描述结果 |
| 导出类型：HTML | 备份格式：单文件网页 | |
| 导出类型：MarkDown | 备份格式：文本 | |
| 导出类型：JSON | 备份格式：原始数据 | |
| 增量备份：Full/Last/LastTime/Custom | 只备份新增内容（开关） | 行为描述替代枚举 |
| 文件下载方式：Browser/Thunder_Link/... | 下载方式：应用内 / 迅雷 / Aria2 | 去掉缩写 |
| 下载并发数 / 下载间隔 | 下载速度：均衡 / 快速 / 稳妥 | 档位化 |
| WAF 限流 / 稍候重试次数 | （不出现） | 引擎内部自动处理，仅日志保留 |
| 备份目标目录 | 保存位置 | 全 UI 统一 |
| 历史备份 | 历史备份 → 我的备份 | 时间线叙事 |
| 运行日志 / 导出日志 | 详细报告 / 导出报告 | 弱化控制台感 |

### 5.2 档位 → 引擎参数映射（设置层实现）

| UI 档位 | 映射 |
|---|---|
| 下载速度·快速 | downloadThread=16, downloadSleep=0.5 |
| 下载速度·均衡（默认） | downloadThread=10, downloadSleep=2 |
| 下载速度·稳妥 | downloadThread=4, downloadSleep=5 |
| 只备份新增内容·开 | IncrementType=Last（全部模块） |
| 只备份新增内容·关 | IncrementType=Full |

> 映射逻辑收敛在 `stores/config.ts`，对引擎契约零改动。
>
> 说明：IncrementType 的 `LastTime`（按上次备份时间）与 `Custom`（自定义）不在档位映射内，高级设置保留原枚举；档位映射仅覆盖开关对应的 Full/Last 两档。

### 6.3 实施注意事项（来自现有代码经验）

- **Vue 3.5 的 v-for 迭代 Map**：编译产物将 Map 解构为 `[key, value]` 条目对 + 索引（与文档的 `(value, key)` 不符），任何「按分组渲染」必须先把 Map 转成 `{k, v}` 数组再 v-for，否则分组名显示索引、行数据全为 undefined（本项目已踩坑）。
- **下拉组件复用 CSelect 模式**：列表 Teleport 到 `document.body` 且样式独立声明（`cs-list` 不能依赖 `.cs` 祖先），避免 `position: fixed` 在带 transform 的祖先内偏移。顶栏昵称▼、档位/模块选择器统一走该组件。
- **日志面板**：`report`/日志导出能力随「查看详细报告」折叠区迁移，保留现有「导出日志」IPC。

## 8. 验收标准（ToC 视角）

1. **新手可用**：新用户不看文档，能在 3 分钟内完成「扫码 → 开始备份 → 看到进度」。
2. **零术语**：主流程（概览/备份向导/进行中/完成）无 §5.1 中的技术术语。
3. **功能不丢**：原 App.vue 全部功能（下载明细、日志导出、历史浏览、12-tab 设置、帮助、相册多选）在新结构中可找到。
4. **视觉延续**：复古暖色与印章品牌保留，无违和感。
5. **无回归**：备份/暂停/恢复/取消/下载/打包全部 IPC 行为与重构前一致。
