# 架构全景分析（收尾版）

> 日期：2026-08-31 · 基线：v4.0.0 + 架构改造 P0~P6 全部落地 · 视角：桌面版为主，兼顾与浏览器扩展原版的同源关系

---

## 一、项目总览

本项目是 QQ 空间个人数据备份工具，同一引擎内核支撑两种交付形态：

| 形态 | 位置 | 运行环境 | 状态 |
|---|---|---|---|
| **浏览器扩展（原版）** | `src/js/*`、`原版/` | Chrome MV3 扩展 | 存量维护，作为引擎同步基线 |
| **Windows 桌面版** | `desktop/` | Electron（主进程 + 渲染层 + 隐藏引擎窗口三进程） | 活跃开发，v4.0.0 已发布 |

桌面版对用户的价值闭环：扫码登录 → 选择模块 → 采集下载 → 本地 SPA 产物 → 双击离线浏览。架构改造（P0~P6）在此形态上完成了从「扩展代码直接搬进 Electron」到「五层引擎 + 三进程分工 + 双端单一来源」的重构。

## 二、桌面版总体架构（三进程）

```
┌─ 渲染进程（主窗口）──────────────────────────┐
│ Vue3 + Pinia（auth/config/backup 三 store）  │
│ 四视图（概览/备份向导/历史/设置）+ 纯壳 App   │
│        ▲ backup:progress/log/state-changed   │
│        │ ipc：ui-bridge.mjs（契约白名单桥）   │
└────────┼─────────────────────────────────────┘
         │ invoke/on
┌────────▼─ 主进程 ────────────────────────────┐
│ ipc/*（backup/engine/fs/zip/viewer/...）      │
│ services/：task-machine（状态机唯一裁判）     │
│   engine-bridge（脚本注入/任务上下文 Map）    │
│   download-manager（并发调度/断点续传）       │
│   path-guard（路径守卫收敛点）                │
│   logger（分级+轮转）/ backup-stats /         │
│   state-store（检查点）/ config-store / packager │
└────────┬─────────────────────────────────────┘
         │ executeJavaScriptInIsolatedWorld(100)
┌────────▼─ 引擎窗口（隐藏，加载 qzone）───────┐
│ 主世界：QQ 空间页面本身（无任何桥能力）       │
│ 隔离世界：desktop-adapters → 引擎五层 → runner│
│   全部宿主能力经 engine-bridge preload 白名单 │
└───────────────────────────────────────────────┘
```

**职责边界**（本架构最重要的三条规则）：
1. 主进程是**唯一裁判**：任务状态转移、文件写入、下载调度、历史统计全部在主进程；引擎与渲染层只上报/展示。
2. 引擎窗口**主世界零能力**：QQ 页面拿不到任何 IPC 桥；引擎代码只活在隔离世界。
3. 渲染层**零乐观状态**：busy/paused 由主进程 `backup:state-changed` 派生，组件不得赋值。

## 三、引擎五层（隔离世界内）

| 层 | 目录 | 规模 | 职责 |
|---|---|---|---|
| 采集层 | `engine/collectors/` | 13 文件 / 6079 行 | 纯「从 QQ 空间拿数据」：分页基类、限速、重试、WAF 检测 |
| 任务层 | `engine/tasks/` | 4 文件 / 785 行 | orchestrator 编排 + state 检查点 + progress 指示 + downloader |
| 仓库层 | `engine/repos/` | 3+2 文件 / ~900 行 | convert 标准化 + writer 持久化 + incremental 增量 |
| 导出层 | `engine/exporters/` | 12 文件 / 3740 行 | SPA/HTML/MD/JSON 渲染分发（43 个导出函数） |
| 打包层 | `engine/packagers/` | 2 文件 / 200 行 | zip + manifest/checksum/report + 迅雷链接 |
| 接口层 | `engine/api/` | 5+11 文件 / 4823 行 | rest-urls/network/fs-utils/utils/common + 各模块接口 |
| 委托层 | `engine/modules/` | 11 文件 / 1650 行 | P2 瘦身后：模块编排委托到五层（附 `.p2-bak` 行为基线） |
| 装配 | `api.js` 36 行 / `config.js` 1031 行 | | api.js 由 3800 行瘦身为装配器 |

数据流单向：**collectors → repos（标准化/持久化/增量）→ exporters（按 exportType 分发）→ packagers（zip/manifest）**，tasks 层贯穿编排。引擎不直接碰宿主：所有 chrome.\*/Filer/JSZip/download 能力经 `desktop-adapters`（256 行）→ `engineBridge` preload 白名单 → 主进程。

## 四、横切机制（本架构的关键设计）

### 4.1 双端单一来源（消灭手抄漂移）
- **模块清单**：`shared/modules.json` → 主进程注入 `window.QZONE_MODULES`（引擎）+ 渲染层 import（UI）， Statistics 等 exportable:false 语义一处定义。
- **配置**：`engine/config-spec.json` → `gen-ui-schema.mjs` 生成渲染层 `schema.ts`（表单模型 + defaultSettings）+ `gen-engine-config.mjs` 同步引擎 `Default_Config`（`--check` 模式进 CI）。三方一致性（spec ↔ schema ↔ 引擎）由单测固化，新增配置只需改 spec。

### 4.2 任务状态机（P3-1）
`task-machine.js` 转移表 + guard：非法转移拒绝告警、同态幂等、prepare 自终态可发起。主进程唯一持久化 checkpoint（state-store），渲染层只派生。下载暂停位绑定 taskId（P3-2），任务切换自动失效——P0-1「取消后下载静默排队」的根治点。

### 4.3 增量备份双写双读（P3-3）
`saveBackupItems` 双写产物 `Common/backup-meta.json`（与 storage 同构）；读取产物优先、缺失/损坏/异 uin 回退 engine-storage。产物目录被用户拷走也能独立增量——用例 8（删除产物后全量重备）因此成立。

### 4.4 安全模型（纵深五层）
1. **进程隔离**：三窗口均 `contextIsolation:true` / `nodeIntegration:false`；引擎窗口主世界无桥。
2. **最小 preload**：engine-bridge 仅 `exposeInIsolatedWorld`；ui-bridge 仅白名单契约（`shared/ipc-contract.mjs`）。
3. **来源守卫**：全部 engine:\* 通道经 `assertEngineSender`（引擎窗口 + 主框架 + qzone URL 三重校验），失败返回 FORBIDDEN。
4. **路径守卫**：`path-guard.js` 统一 `resolveWithin/assertWithin`（`..` 显式拒绝 + resolve 包含判定），engine fs 映射与 resource-read 同一实现；窗口外链 http/https 白名单，engine/viewer 窗口弹窗 deny。
5. **任务上下文**：`Map<taskId, Ctx>` 取代全局单例（P5.2），fs 映射/下载印章/统计路由按 taskId 键控，`grep ActiveBackup` 清零验收。

### 4.5 可观测性（P6.1）
引擎 console 包装统一加 `[e:level]` 分级标记 → 主进程白名单透传（qzone 页面噪音无标记即丢弃，取代逐条补正则的黑名单）→ `logger.js`（debug/info/warn/error + stdout 镜像 + `userData/logs/main.log` 10MB×3 轮转）。

## 五、质量门禁

- **CI 四门禁**：typecheck（vue-tsc + tsc）→ eslint（0 error 基线，40 条 any warning 存量）→ vitest **140 项**（引擎等价比对/状态机/下载暂停位/增量元数据/路径守卫/任务上下文/logger/config-spec 一致性）→ build:renderer；另有 config-spec `--check` 与 main 分支构建门禁。
- **行为等价**：P2 迁移以 `modules/*.p2-bak`（基线）与委托层函数体归一化比对固化，回归手段保留。
- **发布冒烟**：`desktop/冒烟清单.md` 9 用例（含 P0 回归项），安装版/portable 双环境签字制。

## 七、技术债与风险（诚实清单）

| # | 事项 | 影响 | 缓解/建议 |
|---|---|---|---|
| 1 | 引擎五层仍为全局命名空间脚本（非 ESM） | MV3/注入约束的延续；tree-shaking 与类型缺失 | 维持现状；若做引擎侧 IDE 化再评估模块化 |
| 2 | `modules/*.p2-bak` 基线入库（11 文件） | 仓库噪音；仅被等价性测试引用 | 已知权衡；测试改 fixture 目录后可移除 |
| 3 | lint 40 条 `no-explicit-any` warning | 渲染层类型强度有限 | 存量豁免清单策略（P1 约定），随改随清 |
| 4 | v1 单活跃任务 | 服务层已 Map 化，UI/状态机仍单任务 | 多任务是产品决策，架构已铺路 |
| 5 | config-spec 未覆盖引擎内部参数（pageSize/randomSeconds/FilterKeyWords/SourceType） | 这些仍是引擎手写 | 按设计：非 UI 暴露字段不纳入，避免 spec 膨胀 |
| 6 | `sandbox:false`（主/引擎窗口） | preload 需要沙箱外能力时的既定取舍 | preload 仅白名单桥且经守卫；升级 Electron 后复评 |
| 7 | 与扩展原版同源（sync-baseline --force 会回退桌面改造） | 双形态维护成本 | sync-baseline 头部注意事项 + 基线版本号；长期建议冻结扩展端功能同步 |
| 8 | electron-updater 未落地 | 用户更新需手动 | 评估文档就绪（generic 静态源，2~3 人日），发布节奏稳定后排期 |
| 9 | 产物字节级 diff 未做严格回归（P2 遗留） | 迁移等价性靠数量级比对 | 冒烟用例 5/8 覆盖；需要时补一次双全量 diff |

## 八、后续路线建议（优先级序）

1. **发布节奏常态化**：按冒烟清单发 4.0.x 修缺陷版 → 落地 electron-updater（评估文档 §3）。
2. **P6 持续项**：冒烟清单逐步自动化（用例 4/5 可脚本化为 e2e）；lint warning 清零。
3. **多任务备份**：UI 并发限制解除 + 状态机多 prepare 支持（服务层已就绪）。
4. **引擎模块化评估**：隔离世界注入契约不变的前提下，构建期 bundle ESM → IIFE，获得类型与测试红利。

---

**总评**：桌面版已完成从「扩展代码迁移」到「独立工程」的转变。五层引擎职责单一、主进程集中裁判、双端单一来源、纵深防御与 140 项单测构成的质量底座，支撑后续迭代的主要风险从「改坏不知道」收敛为「有门禁兜底的已知取舍」。
